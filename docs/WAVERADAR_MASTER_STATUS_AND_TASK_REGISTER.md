## 1. Executive status

WaveRadar is an early-stage, evidence-first spatial-awareness prototype for emergency response. The project has a React/Vite + Capacitor Android codebase, a separately hosted WaveRadar Core service, and a separate invitation-only Research & Validation Lab.

The project is not yet a validated life-safety product. No through-wall sensing, victim localization, spatial accuracy, or operational rescue-performance claim is established by the current phone-only build.

Deployed to WaveRadar Core:

## 6. Product and evidence language

Allowed:
- “Research prototype.”
- “Concept interface.”
- “Experimental sensor-fusion architecture.”
- “Possible human presence” when a tested sensor supports that limited statement.
- “Unverified,” “inferred,” “unknown,” or “unavailable” when appropriate.

Not allowed without independent evidence:
- “Sees through walls.”
- “Victim located at X meters.”
- “Spatial accuracy is X.”
- “Validated rescue system.”
- “Lives saved,” customer counts, certification, government partnerships, or operational deployments.

## 7. Recovery and change-control policy

- Keep the original GitHub repository and prior branches/releases.
- Preserve raw evidence and old diagnostic reports.
- Never delete duplicate files until the combined document has been verified and a recovery copy exists.
- Use a branch and pull request for source changes; merge only after checks pass.
- Use staged deployments and post-deploy endpoint checks.
- Never treat a successful software build as physical validation.
- Never promote a research result directly into the firefighter interface.
